## 2. Les règles (à respecter pour toute nouvelle vidéo)
- Structure PASA : accroche qui frappe en 3 s → problème → aggravation → solution « déjà préparée dans le livre » → produit → CTA « Le lien est juste en dessous ».
- 30 à 45 s pour le livre 1. Une seule idée par vidéo.
- Rien d'inventé. Les exemples du livre sont dits au « tu », jamais comme le témoignage d'une vraie personne. Faits réels : anonymes, sans pays, ville, nom ni montant exact.
- Interdits : « garanti », « zéro risque », « devenir riche » (même à la négative), promesse de gain, faux témoignages, faux compte à rebours, nombre de pages du livre, faux prix barré.
- Toujours montrer de vraies pages du livre / des kits (extraites du PDF téléphone avec `pdftoppm`), recadrées pour enlever les mots interdits et les numéros de page.
- Les écrans « Alibaba » du livre sont des ILLUSTRATIONS (données fictives). Si une pub est refusée pour le logo, faire une version floutée.
- Son : 0,5 s avant le premier mot ; musique ORIGINALE unique par vidéo, très basse (×0,12 + sidechain), peu de bruitages (×0,14), voix toujours devant.
- Chaque vidéo : couleurs, polices, musique, transitions et fin différentes. Jamais de motion design générique.
- Sauvegarder après chaque étape : README + commit + push sur les 3 branches. Ne JAMAIS toucher en dehors de `e-book/`.

## 3. Comment une vidéo est fabriquée (méthode technique)
Un dossier par vidéo (ex. `communication/videos/m2/`) :
- `index.html` : toute l'animation (1080×1920), pilotée par le temps : `window.render(t)` place chaque élément ; `R0(t-0.5)` = temps de la voix.
- `render.mjs` : Playwright prend 30 images/s → `video-muette.mp4`. Aperçu : `node render.mjs preview 3.5 12 20` → `pv/p-3.5.jpg`…
- `audio.py` : musique + bruitages synthétisés (numpy/scipy) → `music.wav`, `sfx.wav`.
- Mixage final (DUR = durée de la vidéo) :
```
ffmpeg -y -i ../voix/X.mp3 -i music.wav -i sfx.wav -filter_complex "[0:a]aresample=44100,aformat=channel_layouts=stereo,adelay=500|500,apad=whole_dur=DUR,asplit=2[v][k];[1:a]volume=0.12[m];[m][k]sidechaincompress=threshold=0.012:ratio=8:attack=25:release=600[md];[2:a]lowpass=f=5000,volume=0.14[s];[v][md][s]amix=inputs=3:normalize=0,alimiter=limit=0.95,loudnorm=I=-14:TP=-1.5:LRA=9[a]" -map "[a]" -t DUR -c:a pcm_s16le mix.wav
ffmpeg -y -i video-muette.mp4 -i mix.wav -map 0:v -map 1:a -c:v libx264 -crf 24 -preset medium -pix_fmt yuv420p -c:a aac -b:a 192k -movflags +faststart -shortest ../NOM.mp4
```
- Les fichiers `pv/`, `fr/`, `*.wav`, `video-muette.mp4`, `render.log` sont temporaires (ignorés par git) : ils se recréent.

### IMPORTANT — reconnaître les voix (leçon de cette session)
Le client envoie souvent les voix ElevenLabs SANS nom. Une erreur a eu lieu (voix M2 posée sur D3) quand on devinait au rythme.
**Toujours transcrire la voix mot à mot avant de monter.** Méthode qui marche dans cet environnement :
1. `pip install faster-whisper` (déjà fait ici).
2. Modèle Whisper « small » (CTranslate2 int8) récupéré via npm (HuggingFace bloqué) :
   paquets `@skillninja/shortmovie-telop-model-p0` à `p3` → concaténer `model.bin.part0..3` en `model.bin`, vérifier `model.sha256`, garder `config.json`, `tokenizer.json`, `vocabulary.json`, `preprocessor_config.json`.
3. Décoder avec ffmpeg en 16 kHz mono float32 et passer le tableau à `WhisperModel(...).transcribe(audio, language='fr', word_timestamps=True)` (la lecture directe du mp3 plante à cause de la version de `av`).
4. Caler chaque animation sur l'horodatage du MOT.
